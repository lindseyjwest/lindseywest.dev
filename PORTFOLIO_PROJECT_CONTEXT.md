# Lindsey West Portfolio — Project Context

## Project Purpose

This project is Lindsey West's long-term professional portfolio website.

The immediate requirement is to satisfy a university Digital Portfolio assignment, but the website should not be treated as a temporary school project. It should be designed to remain useful after graduation and evolve throughout Lindsey's career.

The public domain is:

**lindseywest.dev**

The domain was purchased through Cloudflare.

## Primary Audience

The primary audience is future employers and recruiters.

The website should be relevant to:

- Data engineering recruiters
- Analytics and analytics engineering recruiters
- Software engineering recruiters
- Automation-focused technical roles
- Technical hiring managers
- Professional connections

Secondary audiences include:

- Professors
- Classmates
- Family
- Friends
- Professional peers

The portfolio should be understandable and interesting even to someone who is not deeply technical.

## Career Positioning

The portfolio should present Lindsey as a technical professional working across:

- Data
- Analytics
- Automation
- Software development

The site's emphasis should lean toward:

1. Data engineering
2. Analytics engineering / analytics
3. Automation
4. Software engineering

Software engineering should still be a substantial part of the portfolio.

The site should not lead with Lindsey's status as a Computer Science student. Education is relevant supporting information, but the primary identity should be based on professional technical work and capabilities.

The portfolio should avoid making Lindsey appear narrowly specialized in only one technology or role.

## Professional Identity

The homepage should use a professional technical identity rather than a student-focused title.

Possible positioning directions include:

- Data & Automation Engineer
- Data / Software Engineer
- Data & Analytics Engineer
- Data Analyst focused on engineering and automation

The final title should accurately reflect Lindsey's experience without sounding inflated.

The headline and supporting copy should explain what Lindsey actually does rather than rely only on a job title.

## Desired Impression

A visitor should quickly understand that Lindsey:

- Has real technical experience beyond classroom assignments
- Works with data, analytics, software, and automation
- Can build technical systems that solve practical business problems
- Understands pipelines, databases, reporting, APIs, and application development
- Can work across multiple technologies rather than only one stack
- Has a strong Computer Science foundation
- Values thoughtful, maintainable solutions
- Has personality beyond a generic resume

The portfolio should feel credible enough for recruiters while still being interesting enough that visitors remember it.

## Site Structure

The portfolio will use a **multi-page architecture**.

Initial pages should include:

### Home

The homepage should emphasize **what Lindsey does**.

It should answer, quickly:

- What kind of technical work does Lindsey do?
- What problems does she solve?
- What areas is she strongest in?
- Where can a recruiter see evidence?

The homepage should likely contain:

1. Hero / professional introduction
2. What I Do / capabilities
3. Selected or featured work
4. Short professional background
5. Small personal section
6. Contact / social links

The homepage should not feel like a resume pasted into a browser.

### Projects

A dedicated page for selected projects.

Projects may eventually include:

- Software engineering projects
- Data engineering projects
- Analytics work
- Automation projects
- School projects
- Personal projects

Each project should include, where appropriate:

- The problem
- What was built
- Technologies used
- Lindsey's contribution
- Screenshots or visual examples
- GitHub repository
- Results
- Technical challenges
- Lessons learned

Individual project detail pages may be added later.

### About

The About page should combine professional background with some personality.

It should include:

- Professional background
- Technical interests
- Career direction
- Education
- Selected personal information

A small number of personal photographs may be used here.

Appropriate photo content includes:

- A photo of Lindsey
- A photo of her dog
- Photos related to hobbies or interests

Personal content should make the site more human without turning it into a lifestyle site.

### Experience

Professional experience relevant to:

- Data
- Analytics
- Automation
- Software development

This may later be combined with About if a separate Experience page feels unnecessary.

### Resume

The site should provide an obvious way to download Lindsey's current resume as a PDF.

### Contact

The site should provide professional contact methods and external profiles such as:

- GitHub
- LinkedIn

## Design Direction

The design should be:

- Minimal
- Clean
- Spacious
- Modern
- Professional
- Memorable
- Slightly playful
- Visually polished

Visual references include:

- Apple
- Notion

The site should use a **light-mode-first design**.

Dark mode is not necessary for the initial version.

## Color

Lindsey likes bright colors.

The visual foundation should remain restrained and minimal, with bright colors used intentionally.

Possible uses include:

- Accent colors
- Project categories
- Hover states
- Buttons
- Links
- Small graphic elements
- Section markers
- Interactive details

Avoid turning the entire interface into a multicolor design.

Bright color should create identity against a simple neutral background.

## Personality

The site should have **subtle personality**.

Good examples include:

- Thoughtful micro-interactions
- Interesting hover states
- Small playful pieces of copy
- Unexpected but restrained layout details
- Personal photography
- Strong typography
- Bright accent colors

Avoid:

- Excessive animation
- Gimmicky effects
- Developer-template clichés
- Fake terminal interfaces
- Code raining across the screen
- Overuse of gradients
- Huge animated titles
- Effects that reduce usability

The site should be memorable because it feels intentional, not because it is loud.

## Photography

Photography should be used selectively.

The site may include:

- A professional or casual-professional photo of Lindsey
- A dog photo
- A small number of hobby/lifestyle photos

Photography should primarily appear on the About page or in a small homepage About preview.

The main homepage should remain focused on professional work.

## Tone and Writing Style

Writing should be:

- Professional
- Clear
- Human
- Confident
- Conversational where appropriate
- Concise
- Specific

Avoid:

- Corporate buzzword overload
- Generic motivational language
- Artificially impressive wording
- Excessive adjectives
- Generic developer statements
- AI-generated sounding copy

Examples of language to avoid include:

- "Passionate developer"
- "Leveraging cutting-edge technologies"
- "Results-driven technology professional"
- "Innovative solutions"
- "Dynamic professional"

Claims should preferably be supported by concrete projects, technologies, outcomes, or experience.

## Development Philosophy

The website needs to be built relatively quickly, but the development process should also help Lindsey learn.

AI should act as both an implementation assistant and a teacher.

When generating code, AI should:

- Explain important architectural decisions
- Explain unfamiliar concepts
- Prefer understandable solutions
- Avoid unnecessary abstraction
- Avoid unnecessary dependencies
- Point out tradeoffs
- Recommend maintainable approaches
- Help Lindsey understand code rather than simply producing large amounts of it

Do not overengineer the portfolio.

If a simple implementation accomplishes the goal well, prefer it.

## Source Control

Git and GitHub should be used throughout development.

The portfolio should live in a GitHub repository from the beginning.

Development should use:

- Meaningful commits
- Clear repository organization
- A useful README
- Version control throughout the build

The public website should link to Lindsey's GitHub profile and selected repositories.

## Deployment

The website must be publicly accessible.

Because the domain is managed through Cloudflare, Cloudflare Pages should be strongly considered for deployment.

The final site should use:

**lindseywest.dev**

## Technical Stack

The technical stack has not yet been finalized.

The selected stack should prioritize:

- Fast development
- Maintainability
- Learning value
- Strong GitHub workflow
- Easy deployment
- Good performance
- Responsive design
- Easy addition of new projects
- Minimal unnecessary infrastructure

A strong candidate is:

- React
- Vite
- TypeScript
- CSS or CSS Modules
- Git / GitHub
- Cloudflare Pages

The framework should not be selected merely because it is trendy.

Complexity should only be introduced when it provides a real benefit.

## AI Collaboration Guidelines

When assisting with this project:

1. Do not generate generic portfolio filler.
2. Ask for real information when content requires personal details.
3. Use placeholders when project information has not been decided.
4. Never fabricate projects, metrics, responsibilities, or accomplishments.
5. Explain important code and architecture choices.
6. Keep the project maintainable.
7. Favor reusable components where they genuinely reduce duplication.
8. Avoid unnecessary dependencies.
9. Maintain responsive design.
10. Maintain accessibility.
11. Prefer semantic HTML.
12. Keep visual consistency across all pages.
13. Preserve the professional but subtly playful design direction.
14. Avoid changes that make the site resemble a common AI-generated portfolio template.
15. Point out overengineering when it occurs.
16. Treat the website as a long-term professional asset rather than only a class assignment.
17. Keep the homepage focused on Lindsey's professional capabilities.
18. Do not unnecessarily emphasize student status.
19. Use personal content selectively to make the site feel human.
20. Prioritize clarity and substance over visual gimmicks.
